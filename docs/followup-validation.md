# 후속 검증 결과

기준 브랜치는 PR #6이 병합된 `main`이다. 기준 브랜치에는 입력 유형,
PSF 합성·Wiener·NAFNet, 참조 화질 지표, 조건별 배치 그래프와 GUI용
배치 호출 함수가 있었다. 이번 작업에서는 배치 기본 크기, 분석·복원 크기
기록, 임계값 검증, K 실험, NAFNet 크기·메모리 점검, 수동 PSF와 보고서
표시를 보완했다. 기존 복원 엔진과 모델 가중치는 유지했다.

## 분석 크기 및 임계값

배치의 합성 및 복원은 원본 크기가 기본이다. 분석은 실제 관측
영상에서 최대 512px까지 축소해 수행한다. 원본·분석·복원 크기는 CSV에서
각각 `original_*`, `analysis_*`, `processed_*`으로 구분한다. 각도는
종횡비를 유지한 축소에서도 같은 축으로 해석한다. 지정한 PSF 길이는
복원 영상의 픽셀 단위이며 분석 해상도에서 별도로 추정하지 않는다.

camera·chelsea의 원본과 45°·15px 합성 블러를 검증(4장), astronaut와
같은 PSF를 적용한 버전을 테스트(2장)에 사용했다. 모두 공개 샘플이다.
원본을 기준으로 분할했으며, 파일 해시가 같은 이미지는 검증기가 거부한다.
별도 인코딩과 같은 장면의 파생본은 데이터 준비 단계에서 같은 분할에 넣어야 한다.

| Laplacian 후보 | 검증 정확도 | 검증 F1 | 오탐 / 미탐 |
| ---: | ---: | ---: | ---: |
| 30 | 0.75 | 0.667 | 0 / 1 |
| 100 | 1.00 | 1.000 | 0 / 0 |
| 300 | 1.00 | 1.000 | 0 / 0 |
| 500 | 0.75 | 0.800 | 1 / 0 |
| 1,000 | 0.75 | 0.800 | 1 / 0 |

F1과 정확도가 동률이면 낮은 기준을 선택해 100을 테스트에 적용했다.
2장 모두 맞았다. 하나의 블러 조건과 세 장면에 대한 검증이므로, 이 결과로
기존 운영 임계값을 바꾸지 않았다. 명암 대비와 노출에 민감한 Laplacian
지표 하나로 최종 선명도를 확정하기 어려운 경우 기존 3단계 복원 판단의
`판단 보류`를 유지한다. FFT 0.20·0.30·0.40에서는 각 분할의 선명 샘플에
후보가 없고 블러 샘플에서 후보가 모두 반환됐다. 반환은 방향 정확도와
별개의 수치다. 촬영 원본의 낮은 FFT 점수만으로 선명하다고 판단할 수 없다.

## Wiener K와 PSF 오차

camera와 chelsea에서 동일한 45°·15px PSF를 합성하고 K=0.001,
0.005, 0.01, 0.02, 0.05를 각각 실행했다. 추정 방향 복원에서는
길이 15px를 주고, 오차 시험에서는 방향 +15°와 길이 +4px를 독립적으로
적용했다. 표는 각 조건에서 최고 PSNR이 나온 K를 표시하고, 실험 폴더의
CSV와 그림은 모든 설정을 담는다.

| 이미지 | PSF | 최고 PSNR의 K | PSNR(dB) | 해당 SSIM |
| --- | --- | ---: | ---: | ---: |
| camera | 정답 | 0.005 | 28.693 | 0.8230 |
| camera | FFT 추정 | 0.01 | 26.642 | 0.7617 |
| camera | 각도 오차 | 0.02 | 24.023 | 0.6517 |
| camera | 길이 오차 | 0.02 | 23.873 | 0.6640 |
| chelsea | 정답 | 0.005 | 32.266 | 0.8840 |
| chelsea | FFT 추정 | 0.005 | 32.204 | 0.8821 |
| chelsea | 각도 오차 | 0.02 | 27.830 | 0.7227 |
| chelsea | 길이 오차 | 0.02 | 27.643 | 0.7394 |

정답 PSF도 전달 함수의 작은 값과 8비트 양자화 때문에 완전 복원을
보장하지 않는다. 작은 K는 작은 전달 함수 부근에서 노이즈와 링잉을
증폭하고, PSF 각도·길이 불일치는 주파수의 감쇠 위치를 잘못 복원해
줄무늬나 반복 무늬를 만들 수 있다. 기존 PSF의 합 1, 중앙 정렬,
반사 패딩과 바깥 감쇠를 확인했다. 두 장면의 결과로 기본 K를
교체하지 않았다. 수동 각도가 주어진 촬영 사진은 자동 추정 Wiener와
별도 행·비교 패널에 표시하며 참조 지표는 비워 둔다.

## NAFNet 해상도

Linux CPU에서 동일 관측 영상의 원본 실행과 긴 변 384px 실행을
비교했다. 축소 추론 결과만 원본 크기로 보간하여 같은 기준에 평가했다.
시간은 단회 추론이며 같은 장비에서 재현되는 고정 성능값이 아니다.

| 입력 | 추론 크기 | PSNR(dB) | SSIM | 시간 |
| --- | --- | ---: | ---: | ---: |
| camera 합성 블러 | 512×512 | 29.637 | 0.8411 | 5.77초 |
| camera 합성 블러 | 384×384 | 28.316 | 0.8036 | 1.67초 |
| NAFNet 공식 blurry.jpg | 1280×720 | — | — | 24.48초 |
| NAFNet 공식 blurry.jpg | 384×216 | — | — | 0.95초 |

공식 예제 blurry.jpg는 관측 영상과 수동·자동 Wiener 및 NAFNet을 같은
1280×720에서 시각화했다. FFT용 영상은 512×288이었다.
[NAFNet 공식 예제](https://github.com/megvii-research/NAFNet/blob/main/demo/blurry.jpg)

512×512 camera 합성 사례에서 별도로 256×256 타일 네 개를 CPU에서
추론했다. 각 타일 주변에 0px 또는 48px의 문맥을 붙이고, 출력에서 문맥을
잘라낸 뒤 연결했다. 전체 추론과 비교한 중앙 가로·세로 경계 ±8px 띠의
평균 절대 픽셀 차이는 문맥 0px에서 2.598, 48px에서 0.575였다.
전체 영역 평균 차이는 각각 0.757, 0.347이었다. 문맥을 추가해도
전체 추론과 차이는 남았으며 운영 경로에는 자동 타일이나 자동 축소를
적용하지 않았다.

Windows, 실제 CUDA 메모리 사용량, 사용자 촬영 원본은 미검증이다.
CUDA 점검 명령은 각 해상도의 최고 allocated/reserved 바이트를 기록한다.
GPU에서 타일이 필요한 해상도와 타일 문맥 크기는 추가 측정이 필요하다.
